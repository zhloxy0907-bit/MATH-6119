最终任务：P3 附件分配方案（assignment）设计与说明

接口约束：
α9 只支持 D，因此谁拿 α9，谁就必须承担所有 D 元件。这是整个 assignment 设计中的硬约束。

设计思路：
本部分不是只给出一个随意分配的 assignment.csv，而是给出多个候选方案，并从 workload、高频元件分布和 feeder 连续性三个角度进行比较。这样做的目的是为后续 P4/P5 的任务分配与路径规划提供更有依据的输入。

分法1：Baseline / 平均分配
原理：
E 是最高频元件，对应附件 α5、α6、α7。因此在 baseline 方案中，先将这三个与 E 相关的 attachment 平均分配到三台机器上，再把其余 attachment 按功能搭配分散布置。这样可以避免某一台机器独占所有高频 E 任务。
M1：α6（A/E）、α8（B/C/I）、α9（D）。这一台主要负责低频与特殊元件，其中 α9 单独承担 D。
M2：α1（C/F/G）、α5（E/I）、α3（B/G/H）。这一台负责一部分中高频元件。
M3：α2（C/F/G）、α4（C/H）、α7（E/J）。这一台继续分担中高频元件，并保持 E 相关能力分布。
特点：
该方案强调平均性与可行性，适合作为对照方案。由于 pick 顺序固定为 head1 -> head2 -> head3，因此 head 排列也尽量保持 feeder 从左到右递增。

分法2：Balanced / 高频元件集中处理
原理：
该方案并不是单纯平均，而是让两台机器承担更多高频 C / E / G 元件，形成“高频主力机”；第三台机器则偏向处理低频和特殊元件。这样做的目标是减少三台机器同时频繁访问高频 feeder 的情况，并降低 attachment 能力切换。
M1：α1（C/F/G）、α5（E/I）、α3（B/G/H）。主要负责高频的 C / G / E 元件。
M2：α2（C/F/G）、α4（C/H）、α7（E/J）。继续分担高频 C / E，同时处理部分 H 与 J。
M3：α6（A/E）、α8（B/C/I）、α9（D）。这一台主要负责特殊元件 D 与低频元件 A，同时承担少量 E / C。
特点：
该方案更接近 machine specialization。它的重点不是让三台机器完全平均，而是让机器分工更清晰，从而提高高频 feeder 的利用率。

分法3：Feeder-friendly / Feeder travel 优先
原理：
由于 feeder 在 x 轴上按 A -> J 排列，而机器的 pick 顺序固定为 head1 -> head2 -> head3，因此如果 attachment 顺序与 feeder 坐标方向一致，机器在 pick 阶段的移动会更连续。这个方案优先优化 feeder movement，而不是单纯追求 workload 平均。
M1：α6（A/E）、α8（B/C/I）、α9（D）。pick 顺序大致从左侧 feeder 向中间移动。
M2：α3（B/G/H）、α1（C/F/G）、α5（E/I）。attachment 顺序按 feeder 坐标逐渐右移，减少大跨度跳跃。
M3：α4（C/H）、α2（C/F/G）、α7（E/J）。保持 feeder movement 相对连续，避免 head pick 顺序左右来回。
特点：
该方案的核心目标是降低 feeder 区域的 travel distance，减少 pick 阶段的无效移动，因此更适合和后续路径规划模块结合分析。

方案比较与选择方法：
为了避免 assignment 只是“拍脑袋分配”，我们进一步使用程序自动生成多个 feasible candidates，并用统一评分标准进行比较。评分主要考虑四项指标：component coverage、E-related attachment balance、estimated workload balance，以及 feeder continuity。

当前实现中，程序会自动生成候选分配方案，并输出 assignment_candidate_catalog.csv 与 assignment_evaluation.csv。这样报告中不仅可以展示三个代表性方案，还可以说明这些方案是经过 evaluation 和 selection 得到的，而不是手工随意指定的。

结论：
因此，P3 的工作不仅是生成 assignment.csv，更重要的是建立一个“候选方案生成 + 指标评分 + 代表方案输出”的小型优化流程，为后续 P4/P5 提供结构更清晰、理由更充分的输入。
